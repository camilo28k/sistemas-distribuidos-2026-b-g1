# Resumen de Clase 2 -- Semana 4

**Fecha:** 26 de agosto de 2026  
**Profesor:** Jesús Ariel González Bonilla  
**Tema:** Exposición sobre ingeniería, documentación pendiente y planificación del MVP

Durante la **clase 2 de la semana 4**, realizada el **26 de agosto de 2026** con el profesor **Jesús Ariel González Bonilla**, se realizaron diferentes actividades relacionadas con las exposiciones, la documentación del proyecto y la planificación del MVP.

Durante la clase, unos compañeros realizaron una **exposición relacionada con ingeniería**. Después de la presentación, el profesor realizó algunas correcciones y explicó que el enfoque de la exposición no era el adecuado. Se aclaró la diferencia entre realizar una exposición **sobre ingeniería** y realizar una exposición **de la ingeniería**, haciendo énfasis en que el contenido debía abordar correctamente el concepto y el enfoque solicitado para la actividad.

Posteriormente, el profesor indicó los documentos que debíamos tener preparados para la siguiente semana. Entre ellos se encuentran las carpetas **`03-product`**, **`04-requirements`** y **`05-architecture`**. Estas secciones deben estar avanzadas y organizadas dentro del repositorio `docs`, continuando con el trabajo realizado anteriormente sobre `governance`, `context` y `domain`.

También se indicó que debíamos tener definidos los **dominios que vamos a utilizar en nuestro proyecto**. Esta decisión es importante porque permite establecer las diferentes áreas del sistema y sirve como base para organizar posteriormente la arquitectura, los servicios, los requisitos y las funcionalidades del proyecto.

Otro de los puntos importantes de la clase fue la construcción del **MVP mediante un monolito**. El profesor indicó que debíamos desarrollar el MVP de nuestro proyecto y que este podía abordarse desde diferentes aspectos, como la implementación del código, la configuración de GitHub Actions y el diseño en Figma.

Como equipo decidimos realizar un trabajo más completo con el objetivo de obtener **puntos adicionales**. Por esta razón, no nos limitaremos únicamente a una parte del MVP, sino que buscamos desarrollar el proyecto incluyendo el **código, la base de datos y el frontend**, además de trabajar en la automatización mediante **GitHub Actions** y en el diseño correspondiente en **Figma**.

Finalmente, se indicó que debíamos tener listas las **historias de usuario (HU)** relacionadas con el proyecto. Estas deben contemplar tanto las funcionalidades correspondientes al **monolito que se desarrollará como MVP** como las funcionalidades que harán parte del **proyecto completo**. Esto permitirá diferenciar lo que se implementará inicialmente en el MVP de lo que se desarrollará posteriormente en la solución completa.

En general, la **clase 2 de la semana 4** estuvo enfocada en corregir el enfoque de una exposición, establecer los documentos que debían estar preparados para la siguiente semana y definir las actividades necesarias para avanzar con el MVP. Se estableció como trabajo pendiente completar **Product, Requirements y Architecture**, definir los **dominios del proyecto**, preparar el **MVP como un monolito** y organizar las **historias de usuario tanto del MVP como del proyecto completo**. Como equipo, además, decidimos desarrollar código, base de datos, frontend, GitHub Actions y Figma para buscar puntos adicionales.
